# cc-backfill-lab

CC_Codex 二期（26.11）**数据工程**产品线：**回灌补数台**（Falcon ASGI + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**回灌窗口 → 按日切片计划 → 重放落库 → 覆盖对账**

与现有线正交（不是契约换版、水印、清单、留存、采集/ETL/同步/解析/编排/摄取）。
不碰外仓常见指纹（Feed 归并 / CDC 游标 / 质检签发 / Slicegate 类仓名）。

## 领域

- **所属领域**：数据工程
- **子方向**：数仓与数据湖（历史回灌 / 补数闭环）

| 层 | 选型 |

## 半窗收口（已实现，只走一条路线）

整窗重放中途某片抛错时，**只选「失败片冻结 + 已成片留存」路线，不与整窗回滚路线并存**：

- 出错片置「失败」并冻结片指针（记白话 `error_text`），其后片留「待重放」
- 已成片**不回滚、仍占目标表落点**（半窗行继续占落点），整笔写入历史档 `backfill_archives` 并签发留存号 `RC-{窗口号}-{档内序}`
- 窗口置「失败闭」，记录 `closed_at`；列表亮失败闭标记，失败卡片亮留存号
- 续灌若再败，追加签发新留存号，历史档只追加不去重已有留存

窗态与可灌判定**同一口径**：仅 `失败闭` 可续灌（`resumable = status=='失败闭'`），后端各接口与前端按钮都吃这一字段，偏了一律 409 拒（含对失败闭窗口打单片重放）。

### 续灌纠偏与并发锁

- 续灌只认失败闭：抢窗口行锁（`backfill_locks`）→ 锁内复核状态 → 失败片回「待重放」→ 逐片补灌 → 全绿转「已完成」
- 所有写操作走 `BEGIN IMMEDIATE`（进入即拿 SQLite 库写锁），两个调度同抢续灌时，输家在抢锁处直接得白话 409，不会互相覆盖片指针；锁在 `finally` 释放，无残留
- 出错统一吐白话（如「数据源缺分区，没写进目标表」「正被别的调度写入，抢锁失败」），不抛裸 500

### 状态机

`草稿 → 已计划 → 执行中 →（全绿）已完成`；任一重放故障即 `执行中 → 失败闭`；`失败闭 →（续灌）已完成` 或再败仍 `失败闭`。

### 新增接口（均需登录）

| 方法 | 路径 | 作用 |
|----|------|------|
| GET | `/api/windows/{id}/detail` | 窗口详情四面板数据：残片/详情/失败片/进度目录+留存档、锁、resumable |
| POST | `/api/windows/{id}/replay` | 整窗重放，中途出错当场失败闭 |
| POST | `/api/windows/{id}/resume` | 续灌纠偏（仅失败闭） |
| POST | `/api/windows/{id}/arm-failure` | 挂闸：指定待重放片下一次重放必失败（模拟故障） |

前端「半窗收口」页四面板并排：残片列表 / 窗口详情 / 失败卡片（亮留存号）/ 进度目录（绿=已落库、红=失败、灰=待重放）。

### 验收（两步连跑）

1. **失败闭签发**：挂闸→整窗重放→中途失败闭，进度目录半绿半空，留存号入历史档
2. **续灌纠偏**：续灌→全片已落库、窗口已完成，再跑覆盖对账「片界全齐」，进度目录不再半绿半空

并发验收：两线程同时续灌同一失败闭窗口，仅一个成功，另一个得抢锁 409，片不重复落、无残留锁（见 `tests/test_half_window.py`）。

旧库启动自动幂等迁移（补列、升级窗口表 CHECK、建新表），存量片与窗状态保留。
